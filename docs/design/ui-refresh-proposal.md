# AudioAssist UI 视觉更新讨论稿

状态：已在 `codex/ui-refresh` 分支实现，等待源码版 UI 验收；尚未打包或安装。
实现不修改录音线程、模型、权限、存储或用户数据。

## 目标与边界

让现有功能呈现为成熟、统一的桌面工具。用户确认：允许适当调整按钮结构和位置，
但不能改变按钮功能。原位版保留用于比较，当前推荐讨论重组版。

## 布局方向 02：功能不变，按任务分组

- 左上：Mic / System / Mix、Start Recording、Upload File，构成新录音与导入入口。
- 左侧中部：历史 session 列表。侧栏从 210px 调到 240px，给文件名多一点空间。
- 左下：Models 和 Settings，作为全局管理入口。
- 顶部：转写模型选择，旁边只读展示后端信息；Summary 继续位于右上角。
- 内容顶部：文件标题、状态和 Export，归属于当前 session。
- 内容主体：按用户最新要求，使用紧凑的「时间戳 — Speaker — 内容」三列，不再把 Speaker 单独放在正文上方；保留点击定位和文字编辑能力。
- 内容底部：固定播放控件；录音时展示现有暂停、播放和 Finish 功能。

密度：正文 14px、行高 1.7、段落上下各 12px；缩小标题区和段间距，以增加每屏转写内容。
历史列表顶部操作区仍会占用部分高度，保留独立滚动。
重组版不是删减功能：重命名、删除、重转写、保存等原有条件显示/悬停动作，
正式实施时必须逐项核对保留；当前原型没有完整模拟这些流程。
后端的 `MLX · 本地` 是静态示例，不表示真实 App 当前状态；后端选择仍在 Settings。

## Speaker 与正文编辑

现有 `ui/js/transcript.js` 已提供 `Rename this` / `Rename all`，分别调用
`app.py` 的 `rename_segment_speaker` / `rename_speaker`。批量范围是当前 session
里标签等于旧名称的所有段落，不跨 session，不是声纹识别或全局联系人改名。
正文现有行为是双击编辑，Enter/失焦结束编辑，Escape 放弃，然后显式保存。

新版原型将说话人编辑明确区分为：

- 仅修改这一段（默认）：选择已有 Speaker 或输入新名字，用于纠正识别归属。
- 统一重命名（显示影响段数）：例如当前 session 所有 SPEAKER_00 改成张总。

单段纠错不会影响其他段落。批量操作按当前标签匹配；若把不同人改成相同名字，
后续批量修改会把这些同名段落视为一组，因此正式 UI 应在重名时提示合并风险。
不在本次视觉改版中暗自改变底层 speaker 数据结构。

独立原型已模拟这两种操作和正文编辑/Save changes，仅修改页面内示例数据。
刷新即恢复，不操作真实转写文件。真实 App 中错误提示、保存失败状态仍需专项验证。

正式实现沿用既有持久化 API，调整菜单文字并显示影响段数；相关前端测试覆盖
批量改名和单段纠错的参数、范围与页面更新。

## 当前问题

- 背景、侧栏与工具栏的深灰接近，内容层次不够明确。
- 历史列表和辅助文字偏小、偏暗；正文、时间与说话人的视觉主次可以改善。
- emoji、原生音频控件与普通按钮的视觉语言不统一。
- 粗分栏线和大量相同灰色边框造成较强的工程工具感。
- `ui/js/summary.js` 的 `showForJob()` 会强制展开 Summary；选中 session 等调用会让已经关闭的面板重新出现。

## 两种配色

- A：暖白与柔和灰绿背景，绿色作为主要操作、选择和播放进度的强调色。推荐作为浅色方向。
- B：石墨深色背景，雾青作为强调色，提高正文和辅助文字对比，保留深色使用习惯。

两版共用同一布局、间距和组件结构，不构成两套独立产品设计。
正式配色入口放在 Settings → 外观，提供跟随系统（默认）、浅色和深色，立即生效并保存。
原型顶部切换器只用于对比，不放入正式主界面。

## Summary 行为建议

1. 每次启动默认收起，右上角按钮保留。
2. 只有明确点击 Summary 才展开，不因转写完成或选中历史 session 自动展开。
3. 同一次运行中尊重用户的展开/收起选择；切换 session 只更新内容，不改变面板状态。
4. Summary/Agent 现有功能保留，此次不开发 AGENT-01。

## 视觉调整

- 原位版保留 210px 历史侧栏；重组版使用 240px。均用细分隔线和轻微背景差异区分区域。
- 统一描边图标、按钮圆角、输入框、悬停、选中与禁用状态。
- 正文采用清晰的字号和行距，时间戳降低视觉权重，说话人采用简洁标签。
- 当前播放段落使用浅色背景和窄强调线，其余内容避免过多卡片边框。
- 录音使用明确的录音标识与计时，暂停、恢复和完成仍在现有底部区域。
- 空状态给出简洁提示，不新增与左下角重复的功能入口。

## 原型与后续实施

打开 `ui-refresh-preview.html` 可切换原位/重组布局、两种配色、转写/录音/空状态、展开 Summary。
所有转写、音频和交互都是示例；不连接真实引擎、不申请录音权限、不改写 session。

播放器在稿中采用统一视觉的自定义样式。正式实现若替换原生控件，必须单独验证
键盘操作、拖动定位、音量和辅助功能；第一阶段可以保留原生播放器以控制范围。

第一阶段已在短期分支调整布局、设计变量、排版、图标和 Summary 可见性策略；
不改录音线程、ASR 后端、权限或存储。Summary 启动/切换 session 的可见性、
主题持久化、布局位置和 Speaker 两类修改已补前端测试；仍需全量测试和真实 UI 验收。
