# AudioAssist Token Plan 实时转写方案

日期 2026-11-20。状态为源码候选，长会议和安装包验收待完成。阈值仍为拟议验收目标。

## 使用方式

- 在录音区提供「本地离线」和「Token Plan 云端」两种转写方式。本地是启动时的默认；CPU、MPS、MLX 仍由现有本地模型设置决定。选中云端时显示对应的 Mic、System 或 Mix 音频会在录音期间上传至阿里云。每次开始录音时锁定选择，录音中途不自动切换后端。
- Mic、System、Mix 沿用现有采集、macOS 权限及本地 WAV 保存流程。界面照常更新实时稿，Agent 继续通过 `audioassist recording transcript --active` 和 `--after-seq` 读取新增段落。会中总结以已写入实时稿的音频时点为准。
- 首期范围是桌面边录边转。上传文件后的云端全文转写和云端 WebSocket 属于可单独验收的后续任务。高精度全文转写继续使用已有本地流程和本地说话人分离。

## 现有接点与边界

| 接点 | 当前行为 | 计划变更 |
|---|---|---|
| `src/realtime.py`、`src/native_capture.py` | Mic 和 System/Mix 各自做 VAD、维护采样时间轴并派发短片段；两个串行 ASR worker 都在同一线程加载、运行和关闭其后端 | 保留本地 worker 行为。云端使用共用的片段调度与请求客户端，沿用两个采集入口和当前采样时间轴 |
| `app.py` 的 `start_realtime` 及 `publish_result` | 按录音模式选采集器，实时结果进入同一 UI 回调及 `LiveTranscriptWriter` | 为本次会话明确选用本地或云端，沿用现有发布入口，单独传递云端覆盖进度及缺段状态 |
| `ui/js/app.js`、`app.py`、`src/service.py` | 结束后界面会尝试启动后处理；有实时段落时服务可复用段落，只跑说话人分离 | 云端录音结束后打开本地原音和草稿，提供本地高精度转写入口。合批文字的说话人归属验证通过后，再考虑复用云端段落的后处理 |
| `src/live_transcript.py`、CLI/HTTP/MCP | 以会话目录和稳定序号读取草稿，可分页 | 保留 `{seq, start, end, text}`。另存云端覆盖信息并在现有读接口上提供文档化的可选元数据 |

使用阿里云北京 Token Plan 的 HTTP 语音识别端点，模型固定为 `qwen-audio-3.0-asr-flash`。提交 16 kHz 单声道 WAV，作为 Base64 数据随请求发送。服务文档说明单次最多 5 分钟，可返回文本和词级时间戳。首期以本地帧数计算批次的起止时间。若实测需要把一句拆成多行，再验证词级时间戳的单位、范围和跨批次偏移。单个批次跨越多个说话人时仔细检查后处理归属，实时稿沿用无说话人标签的行为。

## 分段及队列

1. 复用两条采集链路已有的语音活动检测和停顿边界。源码候选按相邻语音段合并，目标约 8 秒一批，第一段进入队列后等待合批最多 6 秒，连续讲话最长约 15 秒提交一次。暂停和结束时尽快送出尾段。合并的音频保留段间短停顿，批次覆盖的原始时间连续且互不重叠。长静音不单独提交。
2. 首版每个会话只允许一个在途 HTTP 请求，结果按音频顺序送入实时稿，避免分页后又插入早于游标的段落。采集回调和 PCM 读取线程只写原音及非阻塞地交接片段，网络编码、I/O、超时和重试由后台处理。给 Mic 云端分支增加连续发言的强制切分上限，避免一直讲话时音频缓冲持续增长。
3. 以约 60 秒待转音频和固定队列容量作为初始上限，兼顾内存和草稿延迟。队列满时记下未提交区间，保持原音录制和已写草稿；调度恢复后优先处理仍在时效内的音频。静音、录音暂停和语音识别漏段分开统计。成功但空文本的可疑语音段纳入待检查区间，不能据此认定草稿完整。
4. 将云端会话进度与草稿分开保存。`processed_through` 表示已处理或明确标记缺段的连续进度，`missing_ranges` 表示其中确认未转出的语音区间。采集已推进但等待返回的尾部属于待处理。先确认对应的文字已落盘，再推进覆盖进度；异常退出后缺少正常收尾标记的会话保留为草稿。草稿发布失败和云端 ASR 缺段分别处理，后一种情况下 Agent 仍能读到已经落盘的文字。

## 权限、密钥和故障恢复

| 情况 | 行为 |
|---|---|
| 未配置 Key | 选择云端时显示配置入口，由用户决定补配还是明确改用本地。启动录音前做本地配置检查 |
| 鉴权失败、模型未开通或套餐耗尽 | 终止该会话的云端请求，提示原因和已转到的时点，录音继续。保留未识别区间供结束后补转 |
| 网络故障、5xx 或请求限流 | 短时故障按总时限最多尝试一次重试。请求结果不确定时保守处理，避免重复扣费。限流进入冷却，尊重服务端给出的等待时间，继续保存本地原音。连接恢复后处理仍在时效内的批次 |
| 暂停、结束或退出 | 暂停后只允许处理暂停前采集的尾段。结束时先关采集和 WAV，再按固定总期限收尾云端任务，初始目标为 10 秒。到期取消网络等待、记录未完成区间并释放会话，阻止迟到结果写入下一场。应用重启后可读旧稿、播放原音并手动本地补转 |
| 草稿有缺段或本地高精度转写取消/失败 | 历史仍能打开原音和已生成的实时稿。只有成功提交新的全文转写后，才将其显示为本次完整稿件 |

开发探针只读取 `QWEN_TOKEN_PLAN_API_KEY`，桌面版本计划从 macOS 钥匙串读取专用凭据。Finder/DMG 启动的 App 不依赖终端读取 `~/.zshrc`。偏好配置只保存提供方选择。请求限定至官方北京 Token Plan 端点并验证 TLS，禁止跨主机重定向。Key、音频、请求体、转写原文均不写诊断日志；诊断只记录脱敏错误类型、时延、请求次数和已发送音频时长。正式上线前确认该套餐条款适用于桌面接入，并以 Token Plan 控制台用量核对 Credits。

## 开发与验收顺序

| 阶段 | 交付 | 验收 |
|---|---|---|
| 1. 独立接口验证 | 在独立测试目录用已配置的 Token Plan Key 和合成语音验证鉴权，确认文本字段和用量统计；再用公开样本比较三种切段策略 | 明确有效端点和错误码，记录首段和稳态 P50/P95 延迟、每分钟请求数、送出音频时长、可观测的 Credits，以及中文 CER、英文 WER 和中英混合关键词。测试素材与实际会议数据隔离 |
| 2. 源码集成 | 在一个短期 `codex/*` worktree 接入可选云端提供方、限时调度与故障状态。测试实例使用独立 App Data、输出目录及 loopback 发现文件，启动前验证路径 | 单测覆盖超时、断网、429 两类错误、认证失败、积压、空响应、暂停尾段和旧会话迟到回调。正常和故障场景下 WAV 持续增长。断网、限流、退出或中断高精度转写后，已有草稿和 WAV 均可从历史读取 |
| 3. GUI、CLI 和长会议 | 增加用户选项和缺段提示，更新 CLI/HTTP/MCP 合约。跑 Mic、System、Mix 源码路径和一场按实际速度播放的 60 分钟公开会议样本 | Agent 在第 40 分钟和结束前分页读稿，游标稳定、无重复或乱序。先以有声批次结束到 CLI 可读的 P95 ≤15 秒为目标；若还出现明显缺段、过量限流或可用性下降，先调整合批和调度。分别记录断网 1 分钟和恢复后的覆盖范围；断网期间本地录音持续 |
| 4. 独立审查与发布 | 评审待合入的准确 commit，审查上传边界、线程所有权、取消、会话存储和旧数据读取 | 运行 `.venv/bin/python -m pytest -q`、`.venv/bin/python -m pytest tests/frontend -q`，并按发布清单走权限及离线验收。决定制作安装包时按 SemVer 升次版本，当前源码为 2.2.1，因此该兼容功能的候选为 2.3.0，实际以届时基线为准 |

源码分支的 `AGENTS.md` 已更新为本地默认、仅显式选择时发送音频。本地模型仍在转写时禁止自动下载。技术验证使用独立 worktree、Python 环境、App Data 和录音输出。

## 2026-11-20 接口与源码试验

4.09 秒合成英文首次调用返回 HTTP 200，文本和词级时间戳均可读，请求耗时 2.54 秒。用同一句合成短语重复六遍，三种切段都识别出六次。这个样本用于校验链路，真实会议准确率和套餐 Credits 尚未验收。

| 音频批次 | 请求数 | 请求中位耗时 | 最长请求 |
|---|---:|---:|---:|
| 4.1 秒 | 6 | 3.77 秒 | 12.83 秒 |
| 8.2 秒 | 3 | 1.24 秒 | 7.42 秒 |
| 24.5 秒 | 1 | 2.24 秒 | 2.24 秒 |

独立 Mic 源码试验向录音回调注入 PCM，并使用真实 Token Plan 和本机 CLI。录音仍处于进行中时 CLI 读到了正确短语，游标查询没有重复段落，停止后读取到了草稿、本地 WAV 和云端收尾状态。调低合批等待后，复测从第一帧到 CLI 可读为 13.34 秒，原始 WAV 为 5.63 秒。这是单次观测，尚未建立会议延迟基线。独立 macOS 钥匙串命名空间已用虚拟凭据完成读写和清理。真实设备权限、System/Mix 的原生采集、一小时实时延迟和断网恢复为待完成的验收项。
